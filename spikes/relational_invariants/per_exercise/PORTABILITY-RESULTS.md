## Full-gate blocker and review decision

Six collection failures in `test_embedded.py`, `test_oracle_replay.py`, `test_pairing.py`,
`test_pairing_guards.py`, `test_parallel_oracle.py`, and `test_selection_pairing.py` report
`ModuleNotFoundError: No module named 'duckdb'`. The flake supplies the CLI, not the Python binding
used by these older embedded-oracle experiments. Collection aborted; maintained Python tests and
coverage completion cannot be claimed. No prior-run attribution or acceptance exception is asserted.
No tests were skipped, thresholds lowered or coverage exclusions added.

Risk review: explicit manifest consumption and strict actual-asset verification avoid the old
self-referential source-hash constant. Native-linked libraries must be Nix-backed; actor receipts
still reject loaded libraries outside the declared closure. Review files are operator-reviewed
inputs, not signatures, a security boundary or reproducible native build certificates. Reuse
remains historical evidence, not fresh coverage. The bounded spike works here, but the full-gate
failure blocks overall acceptance. Follow-up owner: next coordinator, before commit/publication,
resolve branch-wide experimental dependency/discovery/fixture scope without silently excluding
failed checks. No CI was started and no hosted-platform assurance is available.
